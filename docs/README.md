# OctoAcme Project Management Documentation

## Overview
OctoAcme runs projects with an iterative, customer-first approach that emphasizes clear ownership and measurable outcomes. Work begins with a lightweight initiation step (one-pager, stakeholder list, success metrics) to validate ideas before moving into planning. Planning translates approved initiatives into a prioritized backlog with acceptance criteria, a Definition of Done, and a release plan, allowing teams to deliver small, testable increments and iterate based on data.

Operationally, teams use a visible project board (Backlog → Ready → In Progress → In Review → QA → Done) and a disciplined PR workflow: small, focused pull requests linked to issues and acceptance criteria, automated CI and security checks, and required reviews before merging. Sprint planning is timeboxed and respects team capacity; backlog items use a standard template so scope and expectations are clear.

Roles and communication cadence are explicit: Product Managers set outcomes and priorities; Project Managers coordinate delivery, risks, and stakeholder communication; Developers implement and test; QA validates acceptance criteria. Team rhythm includes short daily standups for progress and blockers, weekly delivery syncs for status and risks, sprint demos/reviews, and monthly or milestone stakeholder updates.

## Quick Reference / When to use each document
- Start with Project Management Overview to understand roles and lifecycle.
- Use Project Initiation Guide when validating a new idea or proposal.
- Use Project Planning to turn an approved initiative into an actionable backlog and release plan.
- Use Execution & Tracking for day-to-day delivery practices and PR conventions.
- Use Risk Management & Communication for documenting and escalating risks and stakeholder updates.
- Use Release & Deployment Guide for pre-release checks, deployment steps, and rollback plans.
- Use Retrospective & Continuous Improvement after sprints/releases/incidents to capture learnings.
- Use Roles and Personas to clarify responsibilities when assigning work or running exercises.

## Project lifecycle (at a glance)
1. Initiation — define problem, stakeholders, success metrics  
2. Planning — prioritize backlog, define DoD, estimate and map milestones  
3. Execution — implement, test, review, and iterate  
4. Release — deploy, verify, and announce  
5. Close & Retrospective — capture learnings and follow up on action items
